# Mayday Chat

[English](README.md)

Mayday Chat - мультиплатформенный защищенный чат-клиент на Kotlin Multiplatform для Android, iOS и Desktop JVM (Windows и macOS). Это проект с privacy-first продуктовой моделью: пользователи связываются друг с другом через UUID, который генерирует приложение, а не через номер телефона, почту или публичный социальный идентификатор.

## Возможности

- Создание аккаунта без номера телефона и email.
- Отображение UUID пользователя для ручного обмена контактом.
- Создание личных чатов по UUID другого пользователя.
- Создание групповых чатов и приглашение участников по UUID.
- Отправка текстовых сообщений, изображений, видео и других файлов.
- Saved Messages как личное пространство для заметок и файлов.
- Защита запуска приложения системной разблокировкой устройства, если она доступна.

- Смена темы, редактирование ника и очистка локальных данных приложения.

## Модель приватности

Mayday Chat использует UUID как публичный идентификатор контакта, потому что номер телефона или email напрямую связывают аккаунт с реальной личностью. UUID тоже является идентификатором, но сам по себе он не является персональным контактным данным.

Такой подход делает обмен контактами явным:

- пользователь сам решает, где и кому передать свой UUID;
- для создания аккаунта не нужен доступ к телефонной книге;
- в продуктовой модели нет входа по номеру телефона или email;
- другого пользователя нельзя найти внутри приложения по его личным контактным данным.

Это не обещание полной анонимности. Backend все равно должен обрабатывать служебные данные, необходимые для маршрутизации чатов и доставки сообщений. Цель более практичная: не собирать персональные идентификаторы для входа, если они не нужны для сценария мессенджера.

## Защита данных

Проект построен вокруг клиентской защиты содержимого чатов и данных аккаунта:

- содержимое сообщения подготавливается на клиенте до отправки на сервер;
- полученное содержимое обрабатывается локально до показа в интерфейсе;
- резервная копия аккаунта защищается паролем пользователя;
- локальные данные можно удалить из настроек приложения.

Startup lock - важная часть security model. Ключи чатов и данные аккаунта должны существовать на устройстве пользователя, иначе приложение не смогло бы расшифровывать сообщения и переносить аккаунт между устройствами. Поэтому Mayday Chat не считает локальное хранилище единственной линией защиты. Приложение также использует платформенные security gates перед показом данных аккаунта и запуском чувствительных account-flow.

На разных платформах это реализуется по-разному:

- Android использует системную разблокировку устройства: биометрию или device credentials в зависимости от версии ОС и настроек устройства.
- Windows Desktop использует native credentials prompt с поддержкой Windows Hello там, где это предоставляет система, и fallback на учетные данные текущего пользователя Windows.
- macOS Desktop использует Keychain-backed user presence checks: в зависимости от настроек пользователя это может быть Touch ID, разблокировка через Apple Watch или пароль устройства.
- iOS хранит чувствительные значения аккаунта через Keychain-backed storage, оставляя платформенную защиту за тем же secure storage bridge, который использует общий код приложения.

Общий продуктовый принцип одинаковый для всех targets: UI аккаунта и локально сохраненные encryption material должны быть защищены самым сильным механизмом подтверждения владельца, который предоставляет конкретная платформа.

Низкоуровневые детали протокола, форматы ключей, внутренние host-адреса и значения тестовой среды намеренно не описаны в публичном README.

## Пользовательский сценарий

1. Пользователь открывает приложение и проходит проверку владельца устройства, если она включена.
2. Новый аккаунт создается без ввода персональных контактных данных.
3. Пользователь копирует свой UUID и передает его другому человеку через любой внешний канал.
4. Личный или групповой чат создается по UUID другого пользователя.
5. Сообщения и вложения появляются в списке чатов и на экране переписки.
6. Аккаунт можно сохранить в резервную копию с паролем и импортировать на другом устройстве.

## Архитектура и программные решения

Mayday Chat разделен на общие и платформенные модули.

- `composeApp` содержит общий Compose Multiplatform UI, навигацию, запуск приложения и DI-связки.
- `androidApp` содержит Android entry point.
- `KALog` содержит iOS host project.
- `feature/chat` содержит экраны чатов, presentation state, use cases, repository coordination, создание чатов, приглашения, вложения и backup/import flow.
- `core/network` содержит сетевой клиент и слой интеграции с API.
- `core/preferences` содержит абстракции обычного и защищенного key-value хранения.
- `core/crypto` содержит общие абстракции защиты данных, которые используются в чатах и аккаунте.
- `core/database` подготовлен для задач локальной персистентности.

Проект использует слоистую структуру:

- UI и ViewModel отвечают за состояние экранов и пользовательские действия.
- Use cases делают точки входа в фичи явными.
- Repository-слой координирует сетевые вызовы, локальное состояние, данные аккаунта, состояние чатов и фоновую синхронизацию.
- Platform bridges изолируют Android, iOS и Desktop поведение: выбор файлов, отправку файлов наружу, app lock и локальное защищенное хранение.

### Platform bridges

Общий Kotlin-код отвечает за продуктовый flow, а platform bridges дают доступ к тем возможностям ОС, которые нельзя качественно реализовать один раз в common code:

- проверка владельца при запуске приложения;
- защищенное key-value хранение;
- выбор и отправка файла резервной копии аккаунта;
- выбор, preview, открытие и отправка вложений;
- desktop-specific packaging и поведение жизненного цикла приложения.

Такой подход позволяет держать большую часть chat feature общей, но при этом использовать native security model каждой платформы вместо слабой универсальной абстракции.

### Хранение ключей

Приложение использует общий интерфейс для секретов аккаунта и чатов, но реализация зависит от платформы:

- Android опирается на secure storage возможности Android и настроенную блокировку устройства.
- iOS использует Keychain-backed storage для чувствительных значений.
- Windows Desktop использует Windows-protected local storage и native credential gates.
- macOS Desktop использует Keychain-backed storage и Keychain user-presence checks.

Backup/import аккаунта является частью продукта, поэтому проект балансирует две цели: ключи должны быть защищены локально, но явное действие пользователя все равно должно уметь экспортировать защищенную паролем резервную копию аккаунта. Поэтому README описывает security model на уровне продукта и архитектуры, не раскрывая низкоуровневые форматы ключей.

## Текущий статус

Это публичный проект в состоянии alpha. Он показывает пользовательский flow приложения, cross-platform UI, логику чатов, backup/import аккаунта, platform security bridges и privacy-oriented модель контактов.

Так как проект все еще находится в alpha, возможны проблемы с доступностью серверов, баги в приложении, неполный перевод и недоработанная обработка некоторых edge cases.
