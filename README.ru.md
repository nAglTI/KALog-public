# Mayday Chat

[Русский](README.ru.md) | [English](README.md)

Mayday Chat - мультиплатформенный защищенный чат-клиент на Kotlin Multiplatform для Android, iOS и Desktop JVM. Проект использует Compose Multiplatform для UI, Koin для DI, Ktor для сети и отдельные модули для криптографии, настроек и защищенного хранения ключей.

Этот README намеренно не содержит адресов backend-среды, реальных UUID, ключей, внутренних хостов и низкоуровневых деталей криптографического протокола.

## Что делает приложение

Mayday Chat реализует компактный сценарий защищенного обмена сообщениями:

- инициализирует пользовательскую сессию и показывает UUID текущего пользователя;
- позволяет скопировать UUID и передать его другому пользователю вне приложения;
- создает личные чаты по UUID другого пользователя;
- создает групповые чаты и приглашает участников по UUID;
- открывает чат, показывает текущую переписку и догружает старую историю;
- поддерживает фоновую синхронизацию входящих сообщений и счетчиков непрочитанного;
- умеет полностью очищать локальные данные приложения.

## Как работает приложение

### Пользовательский сценарий

1. При запуске приложение поднимает локальную сессию и получает UUID пользователя от backend-сервиса.
2. На главном экране отображаются UUID пользователя и список доступных чатов.
3. Пользователь может:
   - создать личный чат, указав UUID собеседника;
   - создать групповой чат и затем приглашать участников из экрана чата.
4. При открытии чата приложение показывает доступные сообщения и при необходимости догружает более старую историю.
5. Отправка и получение сообщений синхронизируются в фоне, а UI обновляет превью и непрочитанные сообщения.
6. Действие `Wipe App` удаляет локальный кэш, ключи и настройки.

### Технический поток

- `ChatSessionViewModel` запускает постоянный цикл синхронизации.
- `ChatListViewModel` инициализирует сессию, получает текущий UUID, наблюдает список чатов, создает новые чаты и очищает локальные данные.
- `ChatDetailsViewModel` открывает выбранный чат, отправляет сообщения, загружает старую историю и приглашает пользователей в групповые чаты.
- `OfflineFirstChatRepository` координирует локальный кэш, сетевые вызовы, ключи участников, шифрование/расшифровку и инкрементальную синхронизацию.
- Входящие сообщения расшифровываются локально перед отображением на экране.

## Как пользоваться

### Базовый сценарий

1. Запустите приложение и дождитесь, пока на главном экране появится ваш UUID.
2. Нажмите `Copy UUID` и безопасно передайте этот UUID другому пользователю.
3. Нажмите `Create Chat`:
   - выберите `Personal`, чтобы создать личный чат по UUID;
   - выберите `Group`, чтобы создать групповой чат.
4. Откройте нужный чат из списка и введите сообщение в поле ввода.
5. В групповом чате используйте `Invite`, чтобы добавить участника по UUID.
6. Если доступна старая история, нажмите `Load older messages`.
7. Если нужно стереть локальные следы работы приложения, используйте `Wipe App`.

### Что важно знать при работе

- Цикл синхронизации стартует автоматически.
- Непрочитанные сообщения считаются только для чатов, которые не открыты в текущий момент.
- Кнопка `Invite` доступна только в групповых чатах.
- На Android и Desktop очистка данных пытается завершить приложение после удаления локального состояния. На iOS приложение не принудительно закрывается, а сбрасывает UI-состояние.

## Защита данных

### Принцип криптографии

Mayday Chat использует асимметричную криптографию как основу для защиты транспортных payload-ов и содержимого сообщений. Ключевой материал создается на устройстве клиента, публичная часть передается туда, где она нужна для обмена, а приватная часть остается на устройстве. Расшифровка содержимого выполняется локально на стороне получателя.

Из соображений безопасности этот README не описывает точные шаги протокола, форматы ключей, параметры алгоритмов и другие низкоуровневые детали реализации.

### Как именно защищаются данные пользователей

- Текст сообщений защищается на клиенте до отправки в сеть.
- При отправке нескольким участникам полезная нагрузка подготавливается отдельно для каждого получателя.
- Защищенные ответы сервера расшифровываются локально до преобразования в UI-модели.
- Приватные ключи хранятся отдельно от обычных пользовательских настроек.
- Приложение умеет одной командой удалить обычные настройки, защищенное хранилище и локальный кэш чатов.

### Локальное хранение

- Android: приватные ключи сохраняются в зашифрованном локальном хранилище с опорой на Android Keystore.
- iOS: приватные ключи сохраняются через Keychain-backed storage.
- Desktop JVM: защищенные настройки сейчас опираются на пользовательские preferences. Для разработки этого достаточно, но для production это слабее системных secret vault-решений, и такой слой нужно усиливать.
- Список чатов и загруженные сообщения в текущей реализации чатового модуля живут в runtime-памяти. Отдельный модуль `core/database` в проекте уже есть, но текущий chat flow еще не переведен на постоянное локальное хранение.

### Важные границы модели безопасности

- Mayday Chat защищает содержимое сообщений и защищаемые payload-ы запросов, но backend все равно обрабатывает служебные метаданные, необходимые для маршрутизации чатов.
- Первичный bootstrap сессии обменивается публичной информацией, которая нужна для дальнейшего защищенного обмена; основной API flow после этого работает через защищенные запросы.
- Прикладная криптографическая защита должна дополнять транспортную защиту и усиление release-конфигурации, а не заменять их.

## Архитектура

Проект разделен на общие и платформенные модули.

### Обзор модулей

- `androidApp/` - Android launcher-приложение.
- `composeApp/` - общий Compose UI, bootstrap приложения и платформенные DI-связки.
- `feature/chat/` - чатовый модуль: presentation, use cases, repository, remote/local sources и chat-specific crypto logic.
- `core/crypto/` - абстракции криптографии, генерация ключей и сервисы шифрования.
- `core/network/` - Ktor client, обертка защищенных запросов, transport security provider и сетевая конфигурация.
- `core/preferences/` - обычное и защищенное key-value хранение с платформенными реализациями.
- `core/database/` - SQLDelight-слой, подготовленный для локальной персистентности.
- `KALog/` - iOS host-приложение и Xcode project.

### Слои

- Presentation layer: Compose-экраны, роуты, диалоги и ViewModel.
- Domain layer: use cases и доменные модели чатов.
- Data layer: repository, API-адаптер, локальный кэш, настройки и хранилище ключей.
- Platform layer: HTTP-клиенты, database drivers, secure settings factories и platform-specific behavior.

## Сборка и запуск

### Требования

- JDK 11+
- Android Studio или IntelliJ IDEA для Android/Desktop разработки
- Xcode на macOS для сборки и запуска iOS
- Доступная совместимая backend-среда вне этого репозитория

### Android

- В IDE: запустите конфигурацию `androidApp`.
- Windows:

```powershell
.\gradlew.bat :androidApp:assembleDebug
```

- macOS/Linux:

```bash
./gradlew :androidApp:assembleDebug
```

### Desktop JVM

- Windows:

```powershell
.\gradlew.bat :composeApp:run
```

- macOS/Linux:

```bash
./gradlew :composeApp:run
```

### iOS

Откройте [KALog.xcodeproj](./KALog/KALog.xcodeproj) в Xcode и запустите target `KALog` на macOS.

## Текущие ограничения и рекомендации перед production

- Текущий chat cache хранится в памяти; persistent storage подготовлен в `core/database`, но пока не используется.
- Для Desktop нужно заменить текущее secure storage на более сильную OS-level интеграцию с секретами.
- Для production-развертывания нужно принудительно включить HTTPS/TLS, ужесточить release-конфигурацию и минимизировать сетевое debug-логирование.
